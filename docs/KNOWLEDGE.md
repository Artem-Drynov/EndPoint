# База знаний и чат

В main включены подготовленные данные для индекса: 227 записей условий, 352 RAG-фрагмента,
а также 200 алгоритмических материалов и 200 решений из трёх MIT-репозиториев.
Источники, закреплённые коммиты и лицензии находятся рядом с данными.
Алгоритмические материалы не являются 200 готовыми заданиями Judge0: генератор адаптирует
контекст, а проверочные тесты формирует отдельно. Исходные решения не исполняются при импорте.

При запуске api entrypoint выполняет миграции и `python -m app.tasks.rag.ingest`.
Импорт сверяет хеши и не дублирует неизменившиеся документы. Данные индекса остаются в volume PostgreSQL.
Полные исходные вложения и миллионы строк таблиц в Git не входят. README корпуса описывает полный локальный датасет,
в main хранится только необходимая для текущего индексатора подготовленная часть.

Запуск всех сервисов из корня:

```bash
sudo docker compose -f compose.yml up -d --build
```

Проверка загрузки:

```bash
sudo docker compose -f compose.yml logs --tail 100 api
sudo docker compose -f compose.yml ps
```

WebSocket: браузер подключается к `/ws/offers/{id}`, frontend проксирует соединение в api,
Redis передаёт события участникам чата. В корневом .env задайте:

```env
FRONTEND_URL=http://195.209.220.175
CORS_ORIGINS=http://195.209.220.175,http://127.0.0.1:3001
```

Если используется HTTPS, добавьте `https://195.209.220.175` в CORS_ORIGINS и поменяйте FRONTEND_URL.
Nginx должен передавать Upgrade и Connection. Пример в deploy/nginx-endpoint.conf.
Ключи GigaChat остаются в серверном .env, в main публикуется только пример настроек.
