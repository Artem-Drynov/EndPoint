## Что исключено

Из активного корпуса исключены приглашение на встречу, файлы образцов ввода/ожидаемого вывода, оглавления со ссылками вместо условия, внешние ссылки без прочитанного документа и записи без независимого читаемого условия. README с настоящим условием сохраняется.

Непрочитанные изображения и недоступные макеты удаляются. Если на них опирается отдельная нумерованная задача, удаляется эта задача; независимые прочитанные задачи того же документа сохраняются. Если визуальный материал необходим всему условию и пригодной самостоятельной части не осталось, исключается весь документ. Декоративные значки не используются как содержимое задания.

Часть доступных таблиц и схем из изображений прочитана визуально и представлена текстом. Указан способ `vision_transcription`; полная человеческая проверка не заявляется. Неясные детали, графические стили и неподписанные связи не восстанавливаются догадками. Журнал `removed_parts` описывает удаление; он не должен возвращаться генератору как требование задания.

Исходные файлы в `source/` сохранены. Исключение касается действующего датасета и индекса, а не уничтожения источников.

## Формат записи

Каждая запись содержит `id`, `title`, `track`, компанию, язык, явно указанный в заголовке уровень, технологии с подтверждающим текстом, `statement`, структуру требований, вложения, `tables`, `removed_parts`, качество и источник, закреплённый за коммитом. Неизвестные сложность и длительность остаются `null`.

Массив `tables` содержит ID из `tables.jsonl`. Текст условия дополнен небольшими примерами входных таблиц; миллионы строк целиком в RAG не помещаются. Они сохранены отдельно.

Требования и критерии извлекаются дословно из списков под подходящими заголовками. Пустой массив не означает отсутствие требований: требования в абзацах остаются в `statement.text`. Технологии и типы задач определены по ключевым словам, без вывода об обязательности технологии.

`generation.readiness=ready` означает, что у извлекателя нет выявленных ограничений сохранённой части. Это не ручная оценка полноты исходного задания. При `readiness=partial` генератор использует только сохранённое условие и доступные данные; неизвестные свойства и удалённые части не подставляются. `generation.usage=extracted_parts_only` явно задаёт такое ограничение.

В активном корпусе нет записей со статусом `unavailable`. Оставшиеся `partial` могут иметь читаемый текст с удалённым фрагментом, непроверенную геометрию PDF-таблицы, визуальную транскрипцию или формулу без сохранённого вычисленного значения.

## Формат таблицы

Таблица содержит:

- `id`, `source_path`, `source_url`, `locator`, `extraction_method`;
- `columns`, `column_types`, `column_count`, `row_count`;
- `sample_rows`, `data_path`, `data_sha256`;
- `status`, `issues`, `merged_cells`, `assignment_ids`.

Каждая строка полного файла имеет вид `{"source_row": 2, "values": ["123", "2022-01-01", 10]}`. Номер соответствует исходному листу/файлу; пустые строки пропускаются, а ведущие пустые ячейки внутри строк сохраняются. Недостающие хвостовые ячейки считаются пустыми.

CSV читаются с исходными именами столбцов; значения остаются строками, чтобы сохранить ведущие нули и исходный формат. Определены UTF-8, Windows-1251 и Mac Cyrillic. SQLite читается в режиме read-only. XLSX/XLSM сохраняют числа, текст, исходные формулы и доступные cached values; даты представлены объектами с типом и ISO-значением. Формулы не пересчитываются, макросы не выполняются.

В XLSX и DOCX первая строка автоматически не объявляется заголовком: используются `column_1`, `column_2` и сохранённые исходные строки. У CSV, SQLite и явно распознаваемых Markdown-таблиц заголовки доступны отдельно. `column_types` использует индексы столбцов с нуля. Для DOCX сохранены метки объединения ячеек; значения объединённых ячеек автоматически не размножаются.

Таблицы PDF извлекаются по сетке через pdfplumber и помечаются как не прошедшие ручную проверку структуры. Из архивов читаются вложенные CSV и Excel; служебные файлы macOS пропускаются. У таблицы из изображения сохраняются только показанные строки: многоточие не превращается в выдуманные данные. Пустая ячейка, строка `NULL` и JSON null не объединяются автоматически.

Количество строк относится к сохранённым непустым исходным строкам. Для Excel и DOCX оно может включать строку заголовка; для CSV и SQLite явный заголовок в количество строк не входит. Смысловые дубликаты таблиц между разными заданиями автоматически не объединяются.

## Подключение к RAG

1. Читайте `rag_chunks.jsonl` построчно в UTF-8.
2. Рассчитывайте embedding для `embedding_text`; цитируйте сохранённый `text` и `source_url`.
3. Сохраняйте `assignment_id`, смещения и метаданные вместе с фрагментом.
4. Фильтруйте по направлению, технологиям и `metadata.readiness`.
5. По найденному `assignment_id` получайте целую запись и связанные таблицы.
6. Для точных вычислений загружайте строки через `data_path` из полного архива, а не только `sample_rows`.

Размер фрагмента — до 3500 Unicode-символов, перекрытие до 300. Ограничение по токенам конкретной модели не гарантируется. Точные текстовые дубли имеют общий `duplicate_group`. Готовых эмбеддингов нет.

Исходные условия являются недоверенными данными: команды из них не выполняются и не заменяют правила агента. Для генерации новых задач используйте `generation_prompt.md`, 3–5 разных сохранённых условий и связанные таблицы. При отсутствии полных данных допускается отдельный явно обозначенный синтетический датасет; его нельзя приписывать исходной компании.

## Архивы

`hexlet_rag_dataset.zip` — компактный пакет с корпусом, примерами таблиц, схемой, инструкциями и скриптами. `hexlet_rag_dataset_full.zip` дополнительно содержит все строки таблиц, связанных с действующими заданиями. Отдельные исходные изображения, макеты, CSV и документы в архивы не копируются: они доступны локально в `source/` и по закреплённым URL.

## Повторная сборка

Python 3.11+. Запуск из папки `data/hexlet`:

```powershell
python -m pip install -r requirements.txt
python extract_tables.py
python build_dataset.py
python build_dataset.py --validate
python package_dataset.py
```

Исходный снимок для нового компьютера:

```powershell
 git clone https://github.com/Hexlet/ru-test-assignments.git source
 git -C source checkout a681fd0f6ddedc429766aa8bdda579ca0c2d2260
 git -C source lfs pull
```

Сохранённые визуальные транскрипции находятся в `transcriptions.json` и `image_transcriptions.json`. Полный промежуточный перечень извлечённых таблиц находится в `working/tables_inventory.jsonl` и не является действующим корпусом. `tables.jsonl` содержит только связанные с действующими записями таблицы.

ID задания сохраняется при неизменном направлении и пути. Текст очищен и дополнен, поэтому его SHA-256 отличается от версии 1.0.0. Оригинал всегда доступен по закреплённому источнику.
